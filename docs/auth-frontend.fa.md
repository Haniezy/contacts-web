# فاز ۶: لندینگ و احراز هویت فرانت

## مسیرها

- `/`: لندینگ بدون هدر، با دکمه‌های ورود و ساخت حساب. پیش‌نمایش‌ها از طرح‌های صاحب پروژه‌اند؛ حرکت ملایم آن‌ها قابل توقف است و با تنظیم کاهش حرکت دستگاه متوقف می‌شود.
- `/signup`: نام، نام خانوادگی، ایمیل، رمز عبور و تکرار آن؛ پس از ثبت‌نام، ستاپ QR باز می‌شود.
- `/login`: ورود با ایمیل و رمز؛ حساب دارای 2FA به `/2fa` و حساب بدون آن به `/contacts` می‌رود.
- `/2fa/setup`: نمایش QR واقعی API، کلید دستی و کپی؛ ادامه به ورود کد شش‌رقمی و فعال‌سازی. پس از فعال‌سازی، ده کد بازیابی یک‌بارمصرف با امکان کپی و دانلود نمایش داده می‌شود. کاربر پس از ذخیره کدها وارد مخاطبین می‌شود.
- `/2fa`: کد برنامه احراز هویت یا کد بازیابی؛ ارقام فارسی و عربی نیز پذیرفته و برای API به انگلیسی تبدیل می‌شوند.
- `/contacts`: مقصد محافظت‌شده با دریافت مخاطبین واقعی کاربر، حالت خالی، خروج و کنترل‌های تم/زبان. طراحی کامل و CRUD فرانت به فاز مخاطبین تعلق دارد؛ این صفحه پیاده‌سازی نهایی آن فاز نیست.

فعال‌سازی 2FA مطابق گزینه «فعلاً رد کن» در طرح اختیاری است. پس از فعال شدن، ورود بدون کد معتبر امکان‌پذیر نیست. بازیابی رمز عبور با درخواست صریح کاربر در این فاز وجود ندارد؛ هیچ لینک یا API نمایشی برای آن اضافه نشده است.

## قرارداد فرم و داده

حداقل رمز عبور API از قبل ۱۲ و حداکثر ۱۲۸ کاراکتر بوده است؛ متن فرم با همین محدودیت هماهنگ است (متن ۸ کاراکتر در تصویر استفاده نشده). نام و نام خانوادگی در مایگریشن `20260929150000_user_names` به مدل User اضافه شدند. نام‌ها در UI اجباری و در API برای سازگاری با کلاینت‌های قبلی اختیاری‌اند؛ نام‌های ارسال‌شده باید ۱ تا ۱۰۰ کاراکتر باشند. تکرار رمز فقط در فرانت اعتبارسنجی می‌شود و به API فرستاده نمی‌شود.

پیام‌های اعتبارسنجی، خطاهای سرور، اتمام نشست، کد اشتباه و محدودیت تعداد تلاش‌ها فارسی/انگلیسی هستند. UI هنگام ارسال درخواست، ارسال تکراری را می‌بندد. رمز قابل نمایش/پنهان‌سازی است؛ برای رمز و ایمیل autocomplete مناسب تنظیم شده است.

QR و راز ستاپ فقط در حافظه همان فرایند UI نگه داشته می‌شوند. پس از رفرش در میانه ستاپ، کاربر رمز خود را دوباره تأیید می‌کند تا QR تازه بگیرد. راز، رمز عبور و کدهای بازیابی در localStorage یا sessionStorage ذخیره نمی‌شوند. کدهای بازیابی فقط همان بار نمایش داده می‌شوند و باید قبل از ترک صفحه ذخیره شوند.

## اتصال و حفاظت

مرورگر فقط با `/api/...` روی دامنه خود فرانت صحبت می‌کند. Route Handler فرانت فهرست محدود مسیرهای مجاز را به بک‌اند Node منتقل می‌کند. `BACKEND_INTERNAL_URL` فقط سمت سرور است؛ در Compose برابر `http://backend:4000` و در اجرای محلی پیش‌فرض `http://127.0.0.1:4000` است. `APP_ORIGIN` فرانت و بک‌اند باید یکسان و برابر آدرس عمومی سایت باشد.

کوکی نشست و چالش 2FA همچنان HttpOnly و SameSite=Lax هستند. فرانت مسیر کوکی‌های دریافتی را به `/` تبدیل می‌کند تا صفحات سروری نیز بتوانند نشست را بررسی کنند؛ کوکی‌های قدیمی API-scoped پاک می‌شوند. اصل JWT و نشست دیتابیس همچنان در بک‌اند اعتبارسنجی می‌شوند؛ وجود کوکی به‌تنهایی اجازه دسترسی نمی‌دهد.

در Next.js 16 فایل `src/proxy.ts` نقش middleware را دارد: نبود کوکی روی مسیر محافظت‌شده را سریع به ورود هدایت می‌کند. صفحه سروری نیز نشست را با `/auth/me` تأیید می‌کند و API مخاطبین مجدداً مالکیت/نشست را بررسی می‌کند. در اختلال بک‌اند، داده محافظت‌شده نمایش داده نمی‌شود.

درخواست‌های تغییردهنده BFF فقط JSON تا ۸ کیلوبایت و Origin مورد اعتماد را می‌پذیرند؛ حجم واقعی بدنه حتی بدون Content-Length کنترل می‌شود. پاسخ احراز هویت کش نمی‌شود و خطاهای داخلی به مرورگر نشت نمی‌کنند. محدودیت تعداد درخواست بک‌اند فعال است؛ در این معماری درخواست‌ها از واسط فرانت می‌رسند و سهمیه IP میان درخواست‌های همان واسط مشترک است. پیش از استقرار عمومی چندکاربره، تشخیص IP واقعی باید فقط با پروکسی مورد اعتماد پیکربندی شود.

## اجرا و تست

```bash
npm run db:migrate
npm run build
npm run lint
npm run typecheck
docker compose up -d --build --wait
```

برای تست مرورگر، `DATABASE_TEST_URL` باید به دیتابیس توسعه/تستِ دارای مایگریشن‌ها اشاره کند. آن را در محیط فرایند تست تنظیم کنید؛ مقدار واقعی در گیت قرار نمی‌گیرد.

```bash
npm --prefix backend run build
npm --prefix frontend run build
cd frontend
npx playwright install chromium
npm run test:e2e
```

تست‌ها بک‌اند اختصاصی روی ۴۱۰۰ و فرانت روی ۳۱۰۰ بالا می‌آورند. مسیر واقعی ثبت‌نام، QR، تأیید TOTP، کد بازیابی، خروج، جلوگیری از ورود با کد غلط، کوکی جعلی، Origin نامعتبر، ولیدیشن، تم/زبان و رفرش در موبایل و دسکتاپ بررسی می‌شود. حساب‌های موقت با UUID ساخته و همان حساب‌ها در پایان پاک می‌شوند. trace مرورگر خاموش است تا رمز و رازهای موقت تست در گزارش ضبط نشوند.
