# فاز یک: دیتابیس و مدل‌ها

PostgreSQL روی Neon قرار دارد و بک‌اند Node.js با Prisma 7 و درایور `@prisma/adapter-pg` به آن وصل می‌شود. فرانت هیچ آدرس اتصال یا دسترسی مستقیمی به دیتابیس ندارد.

پروژه این مرحله در Neon با نام `contacts-web` و شناسه `delicate-mode-87065369` ساخته شده است: PostgreSQL 18، منطقه `aws-eu-central-1` و دیتابیس `contacts`. مایگریشن اولیه روی آن اجرا شده است. آدرس‌های دارای رمز فقط در `.env` محلی قرار دارند.

## مدل‌ها

### User

| فیلد                       | کاربرد                               |
| -------------------------- | ------------------------------------ |
| `id`                       | UUID شناسه کاربر                     |
| `email`                    | ایمیل اجباری و یکتا                  |
| `passwordHash`             | هش رمز، نه رمز خام                   |
| `twoFactorSecretEncrypted` | محل راز رمزنگاری‌شده TOTP، اختیاری   |
| `twoFactorEnabled`         | وضعیت 2FA؛ پیش‌فرض false             |
| `recoveryCodeHashes`       | آرایه هش کدهای بازیابی؛ پیش‌فرض خالی |
| `createdAt` / `updatedAt`  | تاریخ ساخت و آخرین تغییر             |

این فاز ساختار ذخیره‌سازی 2FA را ایجاد می‌کند. تولید/رمزنگاری راز، مدیریت کلید، تأیید کد و مصرف اتمیک کد بازیابی در فاز احراز هویت پیاده‌سازی می‌شوند. نام فیلد به‌تنهایی داده را رمزنگاری نمی‌کند. API ثبت‌نام باید پیش از ذخیره و جست‌وجوی ایمیل، trim و lowercase یکسان اعمال کند؛ یکتایی فعلی PostgreSQL به بزرگی/کوچکی حروف حساس است.

### Contact

| فیلد                      | کاربرد                                                       |
| ------------------------- | ------------------------------------------------------------ |
| `id`                      | UUID شناسه مخاطب                                             |
| `userId`                  | مالک مخاطب؛ کلید خارجی اجباری به User                        |
| `name`                    | نام تا ۲۰۰ کاراکتر                                           |
| `phone`                   | شماره به‌صورت رشته تا ۳۲ کاراکتر؛ برای حفظ صفر اول و علامت + |
| `photoUrl`                | نشانی عکس اختیاری؛ فایل عکس داخل دیتابیس نیست                |
| `birthday`                | تاریخ تولد اختیاری از نوع PostgreSQL DATE، بدون ساعت         |
| `reminder`                | متن یادآوری اختیاری؛ اعلان زمان‌دار هنوز تعریف نشده          |
| `createdAt` / `updatedAt` | زمان‌های دارای منطقه زمانی                                   |

فعلاً هر مخاطب یک شماره دارد. شماره یکتا نیست تا وجود مخاطبین تکراری و قابلیت ادغام آینده ممکن باشد. نرمال‌سازی شماره‌ها و اعتبارسنجی URL/ورودی‌ها در فاز API اضافه می‌شوند. حذف کاربر با `ON DELETE CASCADE` مخاطبین متعلق به او را حذف می‌کند؛ بنابراین API حذف حساب باید این رفتار را در نظر بگیرد.

`@updatedAt` هنگام نوشتن از طریق Prisma به‌روز می‌شود؛ کوئری SQL مستقیم باید مقدار جدید را خودش تعیین کند. UUIDها نیز توسط Prisma تولید می‌شوند.

## ایندکس‌ها

- ایندکس یکتای `User.email`.
- ایندکس ترکیبی `Contact(userId, name)`.
- ایندکس ترکیبی `Contact(userId, phone)`.

چون `userId` اولین ستون هر دو ایندکس است، جست‌وجوی صرفاً بر اساس مالک هم از آن‌ها استفاده می‌کند و ایندکس سومِ تکراری برای `userId` لازم نیست. این ایندکس‌های B-tree برای فیلتر مالک و مرتب‌سازی/جست‌وجوی مناسب همان ایندکس طراحی شده‌اند؛ شتاب‌دهی جست‌وجوی substring مثل `contains` یا `ILIKE '%text%'` تضمین نمی‌شود. در فاز جست‌وجو و بر اساس کوئری واقعی، نیاز به `pg_trgm` بررسی می‌شود.

کلید خارجی و ایندکس‌ها جای مجوز دسترسی را نمی‌گیرند. API آینده باید در تمام خواندن‌ها و تغییرات مخاطب، `userId` کاربر احرازشده را اعمال کند. در این فاز API مخاطبین یا Row-Level Security پیاده‌سازی نشده است.

## اتصال و محیط

در `.env` ریشه:

- `DATABASE_URL`: اتصال pooled Neon با `-pooler` در hostname؛ برای برنامه و seed.
- `DIRECT_URL`: اتصال مستقیم همان دیتابیس و branch؛ برای مایگریشن و Prisma CLI.
- `DATABASE_TEST_URL`: اتصال صریح دیتابیس توسعه/تست، فقط برای تست یکپارچه.

آدرس‌ها از Neon دریافت می‌شوند و نباید کامیت شوند. از `sslmode=verify-full` استفاده کنید. برای هر پردازش بک‌اند یک Prisma Client و pool با سقف ۵ اتصال استفاده می‌شود. متغیرهای محیطی سیستم/Compose نسبت به فایل `.env` اولویت دارند.

## مایگریشن

از ریشه، بعد از `npm run setup` و تنظیم اتصال‌ها:

```bash
npm run db:validate
npm run db:migrate
npm run db:status
```

`db:migrate` همان `prisma migrate deploy` است؛ مایگریشن‌های ثبت‌شده را اعمال می‌کند و به shadow database نیاز ندارد. اجرای دوباره، جدول‌ها را دوباره ایجاد نمی‌کند. مایگریشن اولیه `20260928090000_init` ساخت جدول‌ها، ایندکس‌ها و کلید خارجی را در یک تراکنش انجام می‌دهد.

برای تغییر مدل‌ها در آینده، روی branch توسعه دیتابیس و پس از آماده‌کردن shadow database مستقل و تنظیم `datasource.shadowDatabaseUrl` در `prisma.config.ts`:

```bash
npm --prefix backend run db:migrate:dev -- --name describe_change
```

هر فایل مایگریشن باید پیش از اعمال روی دیتابیس اصلی بازبینی و در Git ثبت شود. از `db push` یا `migrate reset` برای جایگزینی تاریخچه مایگریشن پروژه استفاده نکنید.

## Seed

```bash
npm run db:generate
npm run db:seed
```

Seed یک حساب نمایشی با ایمیل رزروشده `seed@contacts.example` و دو مخاطب ساختگی فارسی/انگلیسی ایجاد می‌کند. رمز حساب به‌صورت تصادفی ساخته، با scrypt و salt مستقل هش و سپس دور انداخته می‌شود؛ این حساب رمز پیش‌فرض قابل ورود ندارد. seed برای داده نمایشی است و خودکار هنگام startup یا مایگریشن اجرا نمی‌شود.

اجرای دوباره با upsert و شناسه پایدار، رکورد تکراری ایجاد نمی‌کند و اطلاعات/رمز موجود را بازنویسی نمی‌کند. اطلاعات تماس فقط نمونه‌اند. راز 2FA خالی و وضعیت آن غیرفعال است.

## بررسی‌ها

```bash
npm run check
npm run db:status
npm run smoke
```

برای تست یکپارچه، `DATABASE_TEST_URL` را در `.env` برای یک دیتابیس توسعه/تستِ مایگریت‌شده تنظیم و اجرا کنید:

```bash
npm run test:db
```

این تست‌ها پیش‌فرض‌ها، فیلدهای اختیاری، تاریخ تولد، فیلتر مالک، زمان ویرایش، حذف آبشاری، یکتایی ایمیل، کلید خارجی و وجود ایندکس‌ها را روی PostgreSQL واقعی بررسی می‌کنند. تمام رکوردهای موقت تست در تراکنش rollback می‌شوند. بدون `DATABASE_TEST_URL` تست دیتابیس اجرا نمی‌شود. تست‌های HTTP معمولی از دیتابیس واقعی مستقل‌اند و پاسخ ۲۰۰/۵۰۳ readiness را بررسی می‌کنند.

`/health` زنده‌بودن HTTP را نشان می‌دهد. `/ready` با `SELECT 1` اتصال واقعی را بررسی می‌کند؛ وجود جدول‌ها را تضمین نمی‌کند، بنابراین باید نتیجه `db:status` هم بررسی شود. هنگام خطا، جزئیات اتصال و رمز در پاسخ HTTP برگردانده نمی‌شود.
